# تصميم: نظام مواعيد ومتابعة مرضى العيادة البيطرية

التاريخ: 2026-11-24 · التسليم: 18.12.2026 23:59

## الهدف ولماذا

مشروع مادة Web Programlama (جامعة صقاريا). المطلوب نظام يغطي كل بنود ملف الواجب، ويستطيع الطالب أن يشرح كل سطر منه في العرض الشفهي. الدرجة تعتمد على أمرين: تحقيق المتطلبات، وفهم الكود.

## الأهداف

- تحقيق كل بنود الواجب: CRUD كامل، 3 أدوار، تعارض المواعيد، آلية الموافقة، REST API مع LINQ وDTO، خادم MCP بثلاث أدوات أو أكثر، لوحة أدمن، README بصيغة تقرير.
- قواعد العمل مكتوبة في مكان واحد (طبقة Services)، وتستعملها MVC وAPI وMCP كلها.
- لا يرى مستخدمٌ بيانات مستخدم آخر بتغيير الـ id في الرابط.

## خارج النطاق

- تعدد العيادات. الواجب يقبل عيادة واحدة، وجدول `Clinic` يبقى لمعلومات العيادة وساعات عملها.
- الدفع الإلكتروني، الإشعارات بالبريد أو SMS، تعدد اللغات.

## ما يعتبر فشلاً حتى لو كان الكود يعمل

- كود معقّد لا يستطيع الطالب شرحه.
- كلمات سر أو مفاتيح داخل الريبو.
- منطق التعارض أو الصلاحيات مكرر بين MVC وAPI وMCP.

## القيود

- .NET 10، EF Core 10 Code First مع migrations، SQL Server عبر Docker، Identity، `ModelContextProtocol.AspNetCore`، Bootstrap 5 وjQuery.
- نموذج البيانات الحالي وأول migration موجودان: نبني فوقهما، ونضيف migrations جديدة عند الحاجة.
- الاختبارات xUnit على SQL Server حقيقي (`SqlServerFixture`)، مع `FakeTimeProvider` للوقت.
- commit بعد كل جزء مكتمل.
- الأدمن: `g231210566@sakarya.edu.tr` / `sau`.

## الطرق التي درسناها

- **أ) شرائح عمودية (اخترناها):** كل خطوة ميزة كاملة من الخدمة إلى الواجهة مع اختباراتها، ثم commit. السبب: شيء يعمل في كل مرحلة، ويسهل فهم كل جزء.
- ب) طبقة طبقة: لا شيء يعمل حتى النهاية، فرفضناها.
- ج) بناء كل شيء دفعة واحدة: كمية كود كبيرة يصعب فهمها قبل العرض، فرفضناها.

## البنية

```
Controllers/ (MVC)   Api/ (REST)   Mcp/ (أدوات MCP)
          \               |              /
           Services/  ← قواعد العمل والصلاحيات
                  |
             AppDbContext (EF Core)
```

- كل خدمة تأخذ "المستخدم الحالي": id وأدوار. هي التي تقرر ماذا يرى وماذا يعدّل، لا الكنترولر.
- الخدمات ترجع نتيجة واضحة (نجاح، أو خطأ مع السبب)، والطبقات العليا تحوّلها: رسالة في الصفحة، أو HTTP 400/404، أو نص يقرؤه المساعد الذكي.

## الأدوار والصلاحيات

| الدور | يستطيع |
|---|---|
| Admin | كل شيء: الخدمات، الأطباء، ساعات العيادة، كل المواعيد والحيوانات، التقارير |
| Veteriner | يرى مواعيده، يوافق أو يرفض (مع سبب)، يضع "مكتمل" ويكتب ملاحظة الفحص، يضيف لقاحاً لحيوان له موعد معه |
| Uye | يسجّل حساباً، يدير حيواناته ولقاحاتها، يحجز ويلغي مواعيده |

- التسجيل العام يُنشئ دائماً حساب Uye. حسابات الأطباء ينشئها الأدمن.
- طلب سجل لا يملكه المستخدم يرجع **404** وليس 403، حتى لا يُعرف أن السجل موجود.

## قواعد المواعيد

- الموعد يُنشأ بحالة `Pending`. `EndsAt = StartsAt + مدة الخدمة`. المدة والسعر يُنسخان إلى الموعد.
- يكون الموعد صالحاً إذا تحققت كل الشروط:
  1. الطبيب نشط ويقدّم هذه الخدمة.
  2. الموعد بالكامل داخل وقت توفر الطبيب لذلك اليوم، وداخل ساعات العيادة.
  3. الموعد في المستقبل.
  4. لا يتداخل مع موعد آخر للطبيب نفسه بحالة Pending أو Approved، حيث التداخل يعني `a.Start < b.End && b.Start < a.End`.
- عند الرفض يرجع السبب بالتركية، ليظهر للمستخدم أو لمساعد MCP.
- الحالات: Pending → Approved/Rejected. Approved → Completed (من الطبيب، مع ملاحظة). Pending/Approved → Cancelled (من المالك).
- السباق بين حجزين في نفس اللحظة: نحجز داخل transaction بمستوى عزل Serializable.
- الأوقات المتاحة تُحسب بخطوة 15 دقيقة.
- الوقت محلي (Europe/Istanbul) ويُخزّن كـ `DateTime` بدون منطقة زمنية. "الآن" يأتي من `TimeProvider`.

## REST API (`/api/...`)

- `GET /api/veterinarians`: كل الأطباء.
- `GET /api/veterinarians/available?serviceId=&date=`: الأطباء المتاحون مع أوقاتهم.
- `GET /api/pets/{id}/vaccines`: اللقاحات السابقة والقادمة (للمالك أو الأدمن).
- `GET /api/reports/services?from=&to=`: عدد المواعيد والإيراد لكل خدمة (للأدمن، مبني على LINQ GroupBy).
- `POST /api/appointments`: حجز موعد، ويرجع 201 أو 400 مع السبب.
- كل الردود DTO وليست entities. الصلاحيات بنفس كوكي MVC.

## خادم MCP (`/mcp`)

- عبر HTTP بحزمة `ModelContextProtocol.AspNetCore`.
- الحماية: `Authorization: Bearer <token>`. المستخدم يُنشئ token من صفحة "MCP Anahtarlarım". يُعرض له مرة واحدة فقط، ويُخزَّن SHA-256 منه في جدول `AccessToken`، مع تاريخ انتهاء وإمكانية إلغاء.
- الأدوات تعمل باسم صاحب الـ token فقط:
  - `uygun_saatler(hizmetId, tarih)`
  - `asi_takvimi(hayvanAdi)`
  - `randevu_olustur(hayvanAdi, hizmetId, hekimId, baslangic)`: أداة كتابة
  - أداة إضافية: `hizmetleri_listele()`
- الاختبار بـ MCP Inspector، ولقطة الشاشة تذهب إلى README.

## الواجهة

- Bootstrap 5، بالتركية، مع validation على جهة العميل (unobtrusive) وجهة الخادم (DataAnnotations في ViewModels إضافة لقواعد الخدمات).
- الصفحات الرئيسية: الرئيسية (الخدمات وساعات العمل)، حيواناتي، مواعيدي، حجز موعد، لوحة الطبيب، لوحة الأدمن (/Admin، Area).
- صورة الحيوان اختيارية: jpg/png حتى 2MB، تُحفظ في `wwwroot/uploads` باسم GUID.
